# Техническое задание: GoGoTerminal (ggterm)

## 1. Общие сведения

**Название проекта:** GoGoTerminal
**Короткое имя:** ggterm
**Язык реализации:** Go
**Целевые платформы:** Windows, Linux, macOS (кроссплатформенность обязательна)

### 1.1 Назначение

Разработка современного полнофункционального терминального приложения, объединяющего в себе:
1. Терминальный эмулятор (аналог Alacritty / WezTerm / Ghostty)
2. Мультиплексор сессий (аналог tmux / zellij)
3. Систему глубокой кастомизации (конфиги, темы, keybindings)
4. Встроенный файловый менеджер с превью (аналог yazi)
5. Поддержку воспроизведения изображений и видео прямо в терминале

### 1.2 Цель

Создать единый бинарник, заменяющий связку «терминал + мультиплексор + файловый менеджер», с современным UX и широкими возможностями кастомизации, без необходимости устанавливать и настраивать несколько отдельных инструментов.

---

## 2. Архитектура (высокий уровень)

Система разбивается на 5 независимых слоёв, взаимодействующих через внутренние интерфейсы (для тестируемости и возможности замены реализации):

```
┌─────────────────────────────────────────────┐
│              UI / Render Layer               │  ← GPU-рендеринг, окно, ввод
├─────────────────────────────────────────────┤
│         Multiplexer / Session Layer          │  ← panes, tabs, сессии, detach/attach
├─────────────────────────────────────────────┤
│   Terminal Emulation Core (VTE + Buffer)     │  ← парсер ANSI/VT, grid, scrollback
├─────────────────────────────────────────────┤
│         PTY / Process Management             │  ← запуск процессов, ввод-вывод
├─────────────────────────────────────────────┤
│   Extension Layer (File Manager, Media,      │  ← yazi-режим, изображения, видео
│   Graphics Protocol, Plugins)                │
└─────────────────────────────────────────────┘
```

Конфигурация и кастомизация проходят «сквозь» все слои как отдельная горизонтальная подсистема.

## 3. Функциональные требования

### 3.1 Terminal Emulator Core

| № | Требование | Приоритет |
|---|---|---|
| 3.1.1 | Поддержка PTY на Windows (ConPTY) и Unix (стандартный pty) | Критично |
| 3.1.2 | Парсер escape-последовательностей: минимум VT100/VT220, xterm-256color, true color (24-bit) | Критично |
| 3.1.3 | Модель буфера: grid ячеек со стилями (цвет, жирность, курсив, подчёркивание, background) | Критично |
| 3.1.4 | Scrollback buffer с настраиваемым лимитом | Высокий |
| 3.1.5 | Поддержка Unicode, включая широкие символы (CJK) и emoji | Высокий |
| 3.1.6 | Поддержка лигатур шрифтов (опционально, через HarfBuzz-биндинги) | Средний |
| 3.1.7 | GPU-ускоренный рендеринг текста (via OpenGL/Vulkan или через ebiten/gl-биндинги) | Высокий |
| 3.1.8 | Поддержка нескольких одновременных терминальных сессий (вкладки/панели) | Критично |

### 3.2 Мультиплексор

| № | Требование | Приоритет |
|---|---|---|
| 3.2.1 | Разбиение окна на панели (splits): горизонтальные и вертикальные, произвольная вложенность | Критично |
| 3.2.2 | Вкладки (tabs), каждая со своим деревом панелей | Критично |
| 3.2.3 | Сессии с возможностью detach/attach (аналог `tmux attach`) | Высокий |
| 3.2.4 | Персистентность сессий через background-демон (unix socket на Linux/macOS, named pipe на Windows) | Высокий |
| 3.2.5 | Управление раскладкой через keybindings (создание/закрытие/навигация по панелям) | Критично |
| 3.2.6 | Синхронизация ввода между панелями (broadcast mode) | Низкий |
| 3.2.7 | Сохранение/восстановление layout сессии между запусками | Средний |

### 3.3 Кастомизация

| № | Требование | Приоритет |
|---|---|---|
| 3.3.1 | Конфигурационный файл в декларативном формате (TOML/YAML) для базовых настроек | Критично |
| 3.3.2 | Скриптуемый конфиг через встроенный язык (Lua через `gopher-lua`, аналог WezTerm) для сложной логики | Высокий |
| 3.3.3 | Система тем (цветовые схемы), поддержка импорта популярных схем (base16, iTerm2 color schemes) | Высокий |
| 3.3.4 | Настройка шрифтов: семейство, размер, fallback-шрифты, лигатуры | Высокий |
| 3.3.5 | Полностью переопределяемые keybindings | Критично |
| 3.3.6 | Hot reload конфигурации без перезапуска | Средний |
| 3.3.7 | Настройка прозрачности, размытия фона, decorations окна | Низкий |
| 3.3.8 | API для плагинов (расширение функциональности сторонним кодом) | Низкий (на будущее) |

### 3.4 Файловый менеджер (режим yazi)

| № | Требование | Приоритет |
|---|---|---|
| 3.4.1 | Многоколоночный (Miller columns) просмотр директорий | Высокий |
| 3.4.2 | Превью файлов: текст с подсветкой синтаксиса | Высокий |
| 3.4.3 | Превью изображений прямо в панели превью | Высокий |
| 3.4.4 | Базовые операции: копирование, перемещение, удаление, переименование, создание | Высокий |
| 3.4.5 | Быстрый поиск/фильтрация файлов (fuzzy find) | Средний |
| 3.4.6 | Интеграция с shell: открытие файла в найденной программе / встроенном редакторе | Средний |
| 3.4.7 | Вызов режима файлового менеджера как оверлея или отдельной панели мультиплексора | Критично |

### 3.5 Мультимедиа (изображения и видео)

| № | Требование | Приоритет |
|---|---|---|
| 3.5.1 | Поддержка отображения растровых изображений (PNG/JPEG/GIF/WebP) в терминале | Критично |
| 3.5.2 | Реализация собственного graphics-протокола между рендерером и приложениями | Высокий |
| 3.5.3 | Совместимость с существующим Kitty Graphics Protocol (для работы сторонних инструментов: chafa, imv, mpv) | Высокий |
| 3.5.4 | Воспроизведение видео (через декодирование кадров, напр. вызов ffmpeg как subprocess или биндинг libav) | Средний |
| 3.5.5 | Управление воспроизведением: play/pause/seek/остановка | Средний |
| 3.5.6 | Аппаратное ускорение декодирования видео (опционально, второй этап) | Низкий |

## 4. Нефункциональные требования

| № | Требование |
|---|---|
| 4.1 | Кроссплатформенность: единая кодовая база для Windows/Linux/macOS с платформо-зависимыми модулями PTY и путей |
| 4.2 | Производительность: рендеринг терминала не должен уступать заметно Alacritty/WezTerm по latency ввода и FPS прокрутки |
| 4.3 | Потребление памяти: разумные лимиты на scrollback и media-кэш, настраиваемые пользователем |
| 4.4 | Стабильность: устойчивость к падению отдельных панелей/процессов без падения всего приложения |
| 4.5 | Расширяемость: модульная архитектура, позволяющая добавлять функциональность (плагины) без переписывания ядра |
| 4.6 | Документация: README, документация конфигурации, примеры тем и keybindings |

## 5. Технологический стек (предложение)

| Компонент | Технология |
|---|---|
| Язык | Go |
| PTY (Unix) | `github.com/creack/pty` |
| PTY (Windows) | ConPTY API (`github.com/UserExistsError/conpty` или собственная обёртка) |
| Рендеринг | OpenGL через `github.com/go-gl/gl` + `go-gl/glfw`, либо `ebiten` как более высокоуровневый вариант |
| Парсинг шрифтов | FreeType-биндинги / `github.com/golang/freetype`, HarfBuzz для лигатур (опционально) |
| Скриптуемый конфиг | `github.com/yuin/gopher-lua` |
| Декларативный конфиг | TOML (`github.com/BurntSushi/toml`) |
| Видео-декодирование | ffmpeg как subprocess, либо `github.com/asticode/go-astiav` |
| Межпроцессное взаимодействие (демон) | Unix domain sockets / Windows named pipes |
| Fuzzy-поиск (файловый менеджер) | `github.com/sahilm/fuzzy` или аналог |

## 6. Этапы разработки (Roadmap)

### Этап 1 — MVP терминального эмулятора
- PTY-слой (кроссплатформенно)
- Базовый парсер ANSI/VT
- Простой текстовый рендер (без GPU, можно временно на стандартном windowing)
- Одна сессия, без мультиплексора

### Этап 2 — Мультиплексор
- Панели и вкладки
- Keybindings для управления layout
- Базовая персистентность сессий

### Этап 3 — Кастомизация
- Конфиг-файл (TOML)
- Темы и шрифты
- Скриптуемый конфиг (Lua)

### Этап 4 — GPU-рендеринг и полировка эмулятора
- Переход на GPU-рендеринг текста
- True color, лигатуры, оптимизация производительности

### Этап 5 — Графика (изображения)
- Собственный graphics-протокол
- Совместимость с Kitty Graphics Protocol
- Отображение изображений в терминале

### Этап 6 — Файловый менеджер
- Miller columns UI
- Превью текста и изображений
- Базовые файловые операции

### Этап 7 — Видео
- Интеграция с ffmpeg/libav
- Воспроизведение видео как последовательности кадров через graphics-протокол
- Управление воспроизведением

### Этап 8 — Расширяемость и релиз
- API плагинов
- Документация
- Тестирование на всех целевых платформах, релиз v1.0

## 7. Открытые вопросы (требуют решения по ходу проекта)

- Выбор конкретной GPU-библиотеки рендеринга (go-gl vs ebiten vs собственный Vulkan-биндинг)
- Формат хранения конфигурации сессий мультиплексора для restore
- Объём совместимости с tmux-конфигами/командами (нужна ли миграция для существующих пользователей tmux)
- Стратегия декодирования видео: subprocess ffmpeg (проще, но накладные расходы на IPC) vs нативный биндинг libav (сложнее, но быстрее)
- Приоритет платформы: разработка ведётся на Windows — нужно заранее решить, как тестировать Unix-специфичные части (PTY, sockets) в CI
